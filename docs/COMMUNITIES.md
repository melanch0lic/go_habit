# Каталог привычек и сообщества

## Модель

| Понятие | Где хранится | Примечание |
|---|---|---|
| Шаблон привычки | `public.habit_template` | Справочник, только миграциями. Тексты `{"ru", "en"}`, эмодзи, рекомендуемая цель, `schedule = 'daily'`, `scoring_policy = 'weekly_consistency_v1'`. |
| Сообщество | = шаблон | Одно постоянное сообщество на шаблон, отдельной таблицы нет. |
| Членство | `public.community_membership` | `unique (user_id, template_id)`, `joined_on`, необязательный `habit_id` — привычка для рейтинга. |
| Личная привычка и отметки | `habit`, `habit_completion` | Без изменений; привычка для рейтинга — обычная личная привычка. |

## Сценарий

- **Вступление** — на выбор:
  - создать привычку по шаблону со своими параметрами (название, цель в день): она добавляется в личный список и
    участвует в рейтинге;
  - вступить без участия в рейтинге.
- **Позже** участник без привычки для рейтинга (или если она удалена) может в любой момент создать её по шаблону.
- **Существующие привычки не привязываются.** Если похожая уже есть, шторка лишь предупреждает об этом, чтобы не
  создать дубликат случайно.
- **Выход** удаляет только членство: привычка остаётся в списке вместе с историей.
- **Создание привычки** — локальная операция (`HabitRepository`), затем `syncNow()` и `join_community` с `habit_id`.
  Если привычка не дошла до сервера или сервер отказал, созданная привычка удаляется, а членство не меняется — повтор
  не оставит дубликата.

## Правило рейтинга `weekly_consistency_v1`

- Неделя — с понедельника по «сегодня» пользователя (`p_today`; сервер принимает только `UTC-дата ± 1 день`).
- Все привычки ежедневные, поэтому каждый день — запланированный.
- Засчитываемые дни: с max(начало недели, `joined_on`, день создания привычки по UTC) по `p_today`.
- Выполнено: число различных дней с отметкой (без tombstone) в этом диапазоне.
- `consistency = выполнено / засчитываемые × 100`, полная точность; в UI округляется.
- Без рейтинга: нет привычки для рейтинга, она удалена или на паузе, нет засчитываемых дней.
- Порядок: процент ↓, выполненные дни ↓, затем стабильный внутренний порядок (id наружу не отдаётся).
- Та же логика в `WeeklyConsistency` (Dart) — для личного прогресса на устройстве.

## Безопасность

- `habit_template`: `select` для `authenticated`, запись — только миграциями.
- `community_membership`: RLS «только свои строки». Колоночные права: `insert (template_id, habit_id, joined_on)` —
  `user_id` всегда `auth.uid()`; `update (habit_id)` — сообщество и дата вступления неизменяемы.
- Составной FK `(habit_id, user_id) → habit (id, user_id)`: чужую привычку не указать. Уникальный индекс по
  `habit_id`: одна привычка — максимум в одном сообществе. Триггер `community_membership_guard`: закрытые
  сообщества, удалённые привычки, `joined_on` вне `UTC ± 1 день` → сегодня.
- `join_community(template, habit, joined_on)` — `security invoker`, идемпотентный.
- `community_leaderboard`, `community_member_counts` — `security definer`, `search_path = ''`, проверяют
  `auth.uid()`; отдают только место, никнейм и аватар (если `stats_visibility` участника это позволяет, иначе
  «Участник»), `public_id` для перехода в профиль, признак «это я» и числа.
  `_community_scores` клиентам недоступна. Счёт и место не хранятся и не записываются клиентом.

Миграции: `20261009130000` (каталог, членство, рейтинг) → `20261009140000` (временно убрала привязку) →
`20261009150000` (вернула привычку для рейтинга). Удалённо не применялись; перед первым деплоем их можно склеить.
Проверки: `supabase/tests/database/02_communities.test.sql` (44 pgTAP-проверки).

## Клиент

- `lib/feature/communities/` — модели, `CommunityRepository`, BLoC каталога и экрана сообщества, экраны.
- Отдельная вкладка «Сообщества»: `/community_routes/communities[/<templateId>]`.
- Drift v5: кэши `habit_templates` и `community_memberships` (с `habit_id`) — каталог и членство видны офлайн и после
  перезапуска.
- Вступление, выход, создание привычки для рейтинга и рейтинг требуют сети. Рейтинг обновляется после действий,
  по pull-to-refresh и после синхронизации (`SyncService.onSynced`).

## Ограничения

- День создания привычки сервер берёт по UTC; западнее UTC первый день может не засчитаться.
