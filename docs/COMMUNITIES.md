# Каталог привычек и сообщества

## Модель

| Понятие | Где хранится | Примечание |
|---|---|---|
| Шаблон привычки | `public.habit_template` | Справочник, только миграциями. Тексты `{"ru", "en"}`, эмодзи, рекомендуемая цель на одно выполнение, рекомендуемое расписание (`schedule`, `weekly_target`, `schedule_days` — как у `habit`), `scoring_policy = 'weekly_consistency_v2'`. |
| Сообщество | = шаблон | Одно постоянное сообщество на шаблон, отдельной таблицы нет. |
| Членство | `public.community_membership` | `unique (user_id, template_id)`, `joined_on`, необязательный `habit_id` — привычка для рейтинга. |
| Личная привычка и отметки | `habit`, `habit_completion` | Без изменений; привычка для рейтинга — обычная личная привычка со своим расписанием. |
| История расписания | `public.habit_schedule_version` | Версии расписания и паузы привычки; пишет только триггер, клиентам недоступна. |

## Каталог

39 шаблонов в семи существующих категориях (миграция `20261011120000_catalog_and_weekly_rankings.sql`):

| Категория | Шаблоны |
|---|---|
| Обучение (`education`) | чтение, английский, иностранный язык, учёба (курс), программирование, повторение |
| Спорт (`sport`) | зарядка, бег, силовая, велосипед, растяжка, йога |
| Здоровье (`health`) | прогулка, вода, режим сна, без сладкого, сбалансированное питание, свежий воздух, утренний ритуал |
| Саморазвитие (`selv-development`) | медитация, дневник, дыхание, время без экранов, порядок дома, подготовка к завтра, расхламление |
| Творчество (`art`) | рисование, музыка, письмо, фотография, личный проект |
| Работа (`work`) | фокус-сессия, приоритеты дня, профессиональный навык, план на неделю, итоги недели, порядок на рабочем месте |
| Финансы (`money`) | учёт расходов, обзор финансов |

- Отдельных категорий для ментального здоровья и дома нет, поэтому такие шаблоны отнесены к «Саморазвитию»
  (порядок на рабочем месте — к «Работе»). Новые категории не добавлялись.
- Расписание хранится структурно: например, у `strength-training` — `weekly_target = 3`, у `deep-work` —
  `weekdays` с маской 31 (Пн–Пт). В описании частота не дублируется.
- Загрузка — `insert … on conflict (id) do update`: id сохраняются, существующие 16 шаблонов обновлены на месте
  (тексты, рекомендации, порядок), новые добавлены. `is_active` не трогается, ничего не удаляется. Повторный запуск
  ничего не дублирует.
- Рекомендация только предзаполняет форму новой привычки. Расписание можно изменить; шаблон и уже созданные привычки от
  этого не меняются.
- В каталоге есть поиск по названию и описанию на обоих языках и фильтр по категории. Карточка показывает
  рекомендуемую частоту, экран сообщества — расписание и цель на одно выполнение.

## Сценарий

- **Вступление** — на выбор:
  - создать привычку по шаблону со своими параметрами (название, цель на одно выполнение, расписание — предзаполнено
    рекомендацией шаблона): она добавляется в личный список и участвует в рейтинге;
  - вступить без участия в рейтинге.
- **Позже** участник без привычки для рейтинга (или если она удалена) может в любой момент создать её по шаблону.
- **Существующие привычки не привязываются.** Если похожая уже есть, шторка лишь предупреждает об этом, чтобы не
  создать дубликат случайно.
- **Выход** удаляет только членство: привычка остаётся в списке вместе с историей.
- **Создание привычки** — локальная операция (`HabitRepository`), затем `syncNow()` и `join_community` с `habit_id`.
  Если привычка не дошла до сервера или сервер отказал, созданная привычка удаляется, а членство не меняется — повтор
  не оставит дубликата.

## Правило рейтинга `weekly_consistency_v2`

- **Период — прошедшая неделя**, с понедельника по воскресенье, перед «сегодня» пользователя (`p_today`; сервер
  принимает только `UTC-дата ± 1 день`). Текущая неделя в рейтинг не входит, пока не закончится.
- **Засчитываемые дни:** с max(понедельник, `joined_on`, день создания привычки по UTC) по воскресенье.
- **Ожидаемые действия по расписанию** — в той версии расписания, что действовала в конце воскресенья (UTC), см. ниже:
  - ежедневная — каждый засчитываемый день;
  - «по дням» — выбранные дни в этом диапазоне;
  - «цель на неделю» — цель, а при неполной неделе `ceil(цель × дней от начала до воскресенья / 7)`.
- **Выполнено:** различные дни с отметкой (без tombstone) среди запланированных, не больше ожидаемого. Отменённая
  отметка не считается, повторная синхронизация и порядок записей результат не меняют.
- `consistency = выполнено / ожидается × 100`, полная точность. В UI один знак после запятой (85,7 %).
- **Порядок:** процент ↓, выполнено ↓, успешные недели подряд ↓, затем стабильный внутренний порядок (id наружу не
  отдаётся). Сортировка идёт по неокруглённым значениям.
- **Успешные недели подряд:** прошедшие недели внутри участия, где выполнено всё ожидаемое; не больше 104 недель назад.
  Это не та же метрика, что серия привычки (`computeStreak`), и с ней не смешивается.
- **Без оценки** (строка «я» с причиной, без процента):
  - `no_habit` — нет привычки для рейтинга или она удалена;
  - `joined_recently` — вступил или создал привычку после той недели;
  - `paused` — привычка была на паузе в конце недели;
  - `no_scheduled_actions` — по расписанию ничего не было запланировано.

  Процент таким участникам не выдумывается, и 100 % «по умолчанию» не ставится.
- **Вышедшие участники** в рейтинг не попадают: выход удаляет членство, и их данные больше не показываются.
- **Текущая неделя** показывается отдельно, на устройстве («Эта неделя (идёт): 2/3 цели недели») по тем же правилам
  до сегодняшнего дня (`WeeklyConsistency.compute`). Учитываются и ещё не синхронизированные отметки.

### История расписания

- `habit_schedule_version` хранит тип расписания, параметры и `is_active` с временем начала действия. Первая версия
  действует с `created_at` привычки, следующие — с серверного времени изменения. Время клиента не используется.
- Записи создаёт триггер `habit_record_schedule_version` при вставке привычки и при изменении расписания или паузы.
  Повторная отправка той же строки синхронизацией новой версии не создаёт. Для существующих привычек миграция создаёт
  версию из текущего состояния.
- Поэтому смена расписания или пауза после воскресенья не переписывает итог прошедшей недели. Изменение, сделанное
  офлайн, вступает в силу, когда дошло до сервера.

### Время

- Недели задаются локальной датой пользователя (`p_today`) и календарной арифметикой — переход на летнее время на
  границы не влияет.
- День создания привычки и время смены расписания сервер берёт по UTC.
- Клиент (`WeeklyConsistency.finishedWeek`) повторяет правило для тех же случаев, что проверяют pgTAP-тесты.

## Безопасность

- `habit_template`: `select` для `authenticated`, запись — только миграциями.
- `community_membership`: RLS «только свои строки». Колоночные права: `insert (template_id, habit_id, joined_on)` —
  `user_id` всегда `auth.uid()`; `update (habit_id)` — сообщество и дата вступления неизменяемы.
- Составной FK `(habit_id, user_id) → habit (id, user_id)`: чужую привычку не указать. Уникальный индекс по
  `habit_id`: одна привычка — максимум в одном сообществе. Триггер `community_membership_guard`: закрытые
  сообщества, удалённые привычки, `joined_on` вне `UTC ± 1 день` → сегодня.
- `join_community(template, habit, joined_on)` — `security invoker`, идемпотентный.
- `community_leaderboard`, `community_member_counts` — `security definer`, `search_path = ''`, проверяют
  `auth.uid()`; отдают только место, никнейм и аватар (если `stats_visibility` участника это позволяет, иначе
  «Участник»), `public_id` для перехода в профиль, признак «это я», числа, успешные недели, начало недели и причину
  для своей неоценённой строки. Ни привычки, ни отметки, ни расписание других участников не раскрываются.
- Внутренние функции (`_community_week_scores`, `_member_week`, `_member_success_weeks`, `_habit_version_at`,
  `_habit_period_counts`) клиентам недоступны. Таблица `habit_schedule_version` закрыта RLS без грантов. Счёт и место не
  хранятся и не записываются клиентом.

Миграции: `20261009130000` (каталог, членство, рейтинг) → `20261009140000` (временно убрала привязку) →
`20261009150000` (вернула привычку для рейтинга) → `20261010120000` (расписания) → `20261011120000` (каталог из
39 шаблонов, история расписания, рейтинг прошедшей недели). Удалённо не применялись.
Проверки: `supabase/tests/database/02_communities.test.sql` и `04_schedules.test.sql`.

## Клиент

- `lib/feature/communities/` — модели, `CommunityRepository`, BLoC каталога и экрана сообщества, экраны.
- Отдельная вкладка «Сообщества»: `/community_routes/communities[/<templateId>]`.
- Drift: кэши `habit_templates` (с v8 — с рекомендуемым расписанием) и `community_memberships` (с `habit_id`) —
  каталог и членство видны офлайн и после перезапуска.
- Вступление, выход, создание привычки для рейтинга и рейтинг требуют сети. Рейтинг обновляется после действий,
  по pull-to-refresh и после синхронизации (`SyncService.onSynced`).

## Ограничения

- День создания привычки сервер берёт по UTC; западнее UTC первый день может не засчитаться.
- Время смены расписания — серверное: если изменение сделано офлайн в воскресенье, а дошло в понедельник, прошедшая
  неделя оценивается по прежнему расписанию.
- Истории членства нет: вышедший и вернувшийся участник оценивается с новой даты вступления.
- Рейтинг считается на лету при каждом запросе; при большом числе участников это стоит проверить на нагрузку.
