# Офлайн-first синхронизация

## Слои

```
UI ──► BLoC ──► Repository ──► Drift (источник истины для UI)
                    │                 ▲
                    └─ requestSync()  │ applyRemote()
                                      │
                               SyncService ◄──► SupabaseSyncRemoteApi ◄──► Supabase (RLS)
```

- **Репозитории** (`HabitsRepositoryImplementation`, `HabitStatsRepositoryImplementation`) пишут только в Drift и
  просят синхронизацию. В сеть они не ходят, поэтому любые операции работают офлайн.
- **UI** подписан на стримы Drift: изменения с сервера появляются на экране сами.
- **`SyncService`** (`lib/core/sync/sync_service.dart`) — единственный компонент, который обменивается данными с Supabase.
- **Категории** — справочник: репозиторий обновляет кэш с сервера при наличии сети и всегда читает из кэша.

## Локальные метаданные

| Поле | Смысл |
|---|---|
| `is_pending_sync` | есть изменения, ещё не принятые сервером |
| `local_version` | счётчик локальных правок; после push флаг снимается, только если версия не изменилась, пока шёл запрос |
| `deleted_at` | локальный tombstone; строка скрыта из UI и удаляется физически после успешного push |
| `sync_state.owner_user_id` | чей это локальный набор данных |
| `sync_state.*_cursor` | максимальный серверный `updated_at`, уже применённый локально |

## Цикл синхронизации

1. **Push привычек**, затем **push выполнений** (выполнение ссылается на привычку). Один batch-upsert на таблицу;
   если сервер отклонил batch (`SyncRejectedException`), строки отправляются по одной — одна невалидная строка
   не блокирует остальные и **не удаляется**, а остаётся pending и пишется в лог.
2. **Pull привычек**, затем **pull выполнений**: `updated_at >= cursor − 5 с`, страницами по 500, по возрастанию.
   Перекрытие в 5 секунд закрывает гонку, когда строка с более ранним таймстемпом коммитится позже.
   Повторное применение строки идемпотентно. Страница и курсор пишутся в одной транзакции.
3. При применении серверных строк **локальные pending-строки не перезаписываются** — они уйдут следующим push.

Запуск: вход в аккаунт, восстановление сети, каждая локальная запись (debounce 800 мс), явный `syncNow()` при выходе.
Запуски сериализованы; запрос во время работающего цикла приводит к ещё одному проходу.

## Ошибки и повторы

| Ошибка | Реакция |
|---|---|
| нет сети / таймаут 30 с (`SyncNetworkException`) | повтор с экспоненциальной задержкой 2, 4, 8… с, максимум 5 мин; при восстановлении сети — сразу |
| 5xx, `40001`, перегрузка (`SyncServerException`) | так же |
| JWT истёк (`PGRST301`, 401) | пауза; `supabase_flutter` обновляет сессию сам, событие auth перезапускает синхронизацию |
| `22xxx`, `23xxx`, `42xxx` (`SyncRejectedException`) | строка остаётся pending, остальные продолжают синхронизироваться |
| сменился пользователь во время запроса | ответ отбрасывается, ничего не применяется |

Успешный локальный write **не означает** успешную отправку: признак — снятый `is_pending_sync`.

## Конфликты

| Ситуация | Результат |
|---|---|
| Одна привычка изменена на двух устройствах | побеждает запись, которую сервер принял **последней** (порядок сервера, а не часы клиента) |
| Привычка удалена на одном устройстве и изменена офлайн на другом | **удаление побеждает**: сервер не снимает tombstone, правка не воскрешает привычку |
| Один день отмечен на двух устройствах | одна запись: одинаковый детерминированный id и `UNIQUE (habit_id, completed_on)` |
| Отметка снята на одном устройстве и поставлена на другом | побеждает последняя принятая сервером |
| Повтор после потерянного ответа | upsert идемпотентен, дубликатов нет |
| Удалена привычка | сервер каскадно помечает её выполнения, другие устройства получают tombstones через pull |

Last-write-wins для полей привычки выбран сознательно: правки редки, поля независимы, цена ошибки — одна
перезаписанная правка названия или описания. Данные о выполнении защищены сильнее: они идемпотентны по дню.

## Аккаунты

- Данные без владельца (свежая установка или апгрейд с v1) забирает первый вошедший пользователь.
- Вход другого пользователя — локальные данные удаляются **до** любой синхронизации; чужие pending-изменения
  не отправляются под новым аккаунтом.
- Выход: `syncNow()` → если остались pending-изменения, пользователь подтверждает их потерю →
  `signOut()` → очистка локальных данных. Справочник категорий сохраняется.
- Если сессия потеряна (refresh-токен отозван), данные остаются: тот же пользователь продолжит с того же места.

## Даты

«Сегодня» — календарный день в часовом поясе устройства (`CalendarDay`), а не окно в 24 часа. Выполнение хранится
как `date` (`completed_on`), без времени. Смена дня во время работы приложения обновляет экран (таймер на полночь).
Ограничение: при переезде в другой часовой пояс уже записанные дни не пересчитываются.

## Апгрейд с v1

Миграция Drift v1→v2 сохраняет все привычки и историю: `last_time_completed` и кэш `habit_completions`
превращаются в записи по дням (без сентинела `2023-03-31`, которым v1 обозначал «отмену»), всё помечается pending
и выгружается в новый бэкенд после первого входа.
